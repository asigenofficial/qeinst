## ترتيب الكود وتنسيق المصدر بالكامل

### خطأ بنيوي في HTML — الـ 42 صفحة كلها كانت غير صالحة
- **حذف وسم `</main>` زائد** كان موجودًا بعد `</footer>` في **كل صفحة** (مخلفات التحويل
  من الـ SPA). النتيجة كانت مستندًا معطوبًا **لا يقبله أي محلل HTML قياسي**
  (ويعني تركيبًا غير متوقع للعناصر في المتصفحات ومحركات البحث).
  الوسم الصحيح يغلق قبل التذييل؛ والزائد أُزيل في الـ 42 صفحة (الموازنة الآن مطابقة 100%).

### تنسيق المصدر (قابلية القراءة)
- كان الـ HTML مضغوطًا في 203 أسطر مع أسطر يبلغ طولها **10,712 حرفًا** — غير قابل للقراءة
  أو المراجعة أو التعديل.
- تنسيق **كل المصدر** بـ Prettier: 42 ملف HTML + وحدات CSS + الـ JS + JSON
  (عرض 120 حرفًا، مسافات بادئة tabs، مع `htmlWhitespaceSensitivity: css` حتى لا تتأثر
  المسافات داخل النص العربي).
- مثال: `index.html` من 203 أسطر مضغوطة إلى بنية متدرّجة واضحة.
- تحقق: ارتفاع الصفحة المرسومة **متطابق تمامًا** قبل وبعد التنسيق (3141px) — صفر تغيير بصري.
- ملاحقة: `assets/css/app.css` مُستبعد من التنسيق لأنه مُولَّد من `src/`.

### أخطاء بصرية إضافية (موجودة في الأصل وليست من الترتيب)
- **شعار التذييل العملاق**: `.brand-logo` كان مُقاسًا فقط تحت `.brand .brand-logo` (الترويسة)،
  وقواعد التذييل تستهدف `<svg>` غير موجود في الـ markup، فظهرت الصورة بمقاسها الطبيعي
  وغطّت التذييل بالكامل → تحديد 43×43px.
- **تداخل روابط القائمة الجانبية للسياسات**: `.policy-menu-btn` مكتوب لـ `<button>`
  (`width:100%`) لكن الصفحات تستخدم `<a>` سطريًا، فتراكمت الروابط فوق بعضها
  → `display: block`.

### ترتيب الصور (الحالة النهائية)
جميع الصور داخل `assets/images/` موزعة على 12 مجلدًا موضوعيًا بأسماء وصفية (kebab-case):

مع صفر ملفات مكررة وصفر مراجع مكسورة.

## إعادة هيكلة المصدر إلى مجلدات أقسام

كانت الصفحات الـ42 كلها مكدّسة في جذر المشروع. الآن كل صفحة داخل مجلد قسمها، مع إعادة كتابة **كل** المسارات نسبيًا.

### البنية الجديدة

```
index.html                 ← الصفحة الرئيسية (تبقى في الجذر إلزاميًا)
404.html                   ← صفحة الخطأ (تبقى في الجذر لتتعرّف عليها الاستضافة)
about/                     about, vision, why-choose-us, methodology, impact, clients
solutions/                 solutions, training-needs, custom-training
programs/                  programs, program-details, closed-program, calendar
trainers/                  trainers, trainer-profile
gallery/                   gallery, gallery-details
news/                      news, articles, article-details
registration/              registration-personal, registration-work,
                           registration-schedule, registration-review,
                           registration-success, request-success
policies/                  policies, terms, integrity, general-privacy,
                           beneficiary-privacy, beneficiary-satisfaction,
                           cancellation-refund, content-freshness,
                           electronic-attendance, trainee-limit
support/                   contact, faq, search-results, system-error
assets/                    css, js, images, docs  (لم تتغيّر)
```

### ما تم تحديثه مع النقل

1. **روابط الصفحات (كل الصفحات الـ42):** أُعيد حسابها نسبيًا حسب موقع كل ملف، مثل
   `programs.html` تصبح `../programs/programs.html` من داخل `policies/`، وتبقى `programs.html`
   من داخل `programs/`. الروابط المرفقة بمرساة (`#top`) حُفظت كما هي.
2. **مسارات الأصول:** أضيف `../` لكل مراجع `assets/` و`components/` في الصفحات العميقة.
3. **مسارات مكتوبة داخل `url(&quot;...&quot;)`:** 4 خلفيات في `news/articles.html` كانت
   بعلامات اقتباس مُرمَّزة كـHTML entities فتجاوزها البحث الأول؛ ظهرت كـ`ERR_FILE_NOT_FOUND`
   في فحص المتصفح وأُصلحت.
4. **`assets/js/app.js`:** الروابط والصور المبنية داخل الـJS كانت ثابتة
   (`programs.html`، `registration-personal.html`، `p.image`) وكانت ستنكسر بعد النقل.
   أُضيف محدّد جذر يقرأ مسار `app.js` نفسه من عنصر `<script>` الخاص به:

   ```js
   const QEI_ROOT = ... self.src.replace(/assets\/js\/app\.js.*$/, "")
   function qeiUrl(path) { return QEI_ROOT + path }
   ```

   هذا يبقى صحيحًا مهما كان عمق الصفحة، **وأيضًا** لو استُضيف الموقع داخل مجلد فرعي —
   وهو أضمن من المسارات المطلقة `/assets/...`.
5. **`sitemap.xml`:** حُدِّثت 40 عنوانًا إلى مساراتها الجديدة (الإجمالي 42).
6. **`tools/qa.py`:** كان يفحص جذر المشروع فقط؛ الآن يمشي على الشجرة كاملة ويحلّ
   كل رابط نسبيًا مقابل مجلد صفحته، وأُضيف فحصان: روابط تخرج فوق جذر الموقع،
   وتوازن وسوم `<main>`.

### ملاحظة للنشر
عناوين URL تغيّرت (مثال: `/about.html` صارت `/about/about.html`). إن كان الموقع منشورًا
ومفهرسًا مسبقًا، أضف تحويلات 301 من العناوين القديمة إلى الجديدة للحفاظ على ترتيب البحث.

### التحقق النهائي
- `tools/qa.py`: **0 ملاحظات على 42 صفحة** (صفر أصول ناقصة، صفر روابط ميتة)
- فحص المتصفح على الـ42 صفحة: صفر تجاوز أفقي، صفر صور مكسورة
- `node --check assets/js/app.js`: سليم
- تحقّق بصري من الرندر داخل `news/` و`policies/`: الأنماط والخطوط والصور والقائمة تعمل

## المرحلة الرابعة — تحليل شامل وتجهيز الواجهات للإنتاج

### منهجية الفحص
تم فحص الموقع بمتصفح حقيقي (Chromium) على الـ 42 صفحة وعلى 8 مقاسات:
1920 / 1440 / 1280 / 1024 / 768 / 560 / 390 / 360 بكسل، بأداتين:

- `ui_audit.mjs` — قياس التجاوز الأفقي، أحجام مناطق اللمس، أخطاء الوحدة الطرفية.
- `ui_verify.mjs` — تفاعل فعلي مع كل صفحة: نقر الأزرار، إرسال النماذج فارغة، تغيير القوائم، فتح النوافذ المنبسقة.

### أبرز الأعطال التي كشفها الفحص وتم إصلاحها

1. **مسار التسجيل معطّل بالكامل**: كان التنقل يعتمد على `window.location.hash`
   (من نسخة الصفحة الواحدة)، ولا معنى له بعد تقسيم الموقع إلى صفحات.
   13 زرًا ونموذجًا لم يكن يفعل أي شيء. أصبح المسار يعمل فعليًا مع حفظ البيانات.
2. **القوائم المنسدلة فارغة**: تصدير Figma أزاح نصوص الخيارات بمقدار واحد،
   فكانت كل قائمة تحمل عنوان القائمة التالية كخيار وحيد. أُعيد بناء 8 قوائم
   بخيارات حقيقية (المجال، الموقع، طريقة التنفيذ، المستوى، التاريخ، نوع التدريب).
3. **130 زرًا و 52 رابطًا بلا أي وظيفة** → صفر الأن.
4. **425 حقلًا بلا تسمية وصول** → صفر الأن.
5. **تجاوز أفقي**: 28 صفحة عند 1024 بكسل + الرئيسية عند 768 → صفر على المقاسات الثمانية.
6. **مناطق لمس أقل من 32 بكسل** على كل الصفحات → الحد الأدنى 40 بكسل على الجوال.
7. **مربعات صور فارغة** في قائمة البرامج القادمة → ملئت بصور البرامج.
